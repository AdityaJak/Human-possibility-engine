# Experiment Registry — Phase II

_Two ledgers. Exploratory results may inform design but never support a claim. Confirmatory results
come only from frozen preregistrations evaluated once on untouched partitions by the Research Director,
and re-run by the Independent Critic._

## 1. Partition rules (fixed before any Phase II model development)

### Synthetic
| Purpose | Seeds | Rule |
|---|---|---|
| development | task/population seeds 1000–1099 | unlimited iteration |
| tuning | 2000–2049 | hyper-parameter selection only; equal budgets per model class, logged |
| **confirmatory** | **500–509** | never run before the freeze; one run per preregistration |

Phase I used seeds 0–9 (and 7, 21, 1001–1003 for tuning); those seeds are **not** confirmatory in
Phase II. New v2 task families are defined by code + task seed; held-out families for Gate C/F are named
in the preregistration and never used in development.

### Human (participant-level)
Split seed **20261105**, stratified by experiment file: dev 40% / tune 20% / **test 40%**. Participant
id lists are generated by `scripts/phase2_partitions.py`, committed under `reports/phase2/partitions/`
with a SHA-256 over the test partition, before any Phase II model is fitted.

**Contact disclosure (corrected after the critic's audit, `reports/phase2/critic/guard_run_1.json`).**
After Phase I, no Psych-101 MCPL or IGT participant is pristine: every one was fitted on or scored,
and the committed Phase I artifacts (`reports/human_validation/exp07_human_heldout/{fits,outcomes}`)
contain **per-participant scores for 63 MCPL and 137 IGT participants who are now in the Phase II test
partition**. Consequences: (a) MCPL and IGT can only be **secondary** Gate D families; the primary
family must be pristine (never used in Phase I): bandits, horizon task, probability/reversal learning
or experience-based choice; (b) per-participant use of any Phase I human artifact is forbidden in
Phase II (aggregate Phase I tables may be cited as history); (c) the protection is enforced in code —
the harness refuses the test partition without a freeze record, every result file lists the
participant keys it scored, and the critic re-runs every confirmatory evaluation. The mandate's
"independent populations" requirement is met only by a second dataset; until then Gate D is reported
with this caveat.

**Minimum-n rule.** A family counts toward a gate only if its pooled test partition has ≥ 30
participants and its tune partition ≥ 15 (so `horizon_task/exp2` (test 3) and `probability_learning`
(test 9) cannot count alone).

**Tuning rule.** Fit on dev, select hyper-parameters (including lapse and every ablation flag) on
tune, score on test; never select on the participants being fitted. Grids are authored by the
human-validation lane, hashed before development, and extended whenever a reference model's chosen
value sits at a grid edge — equal grid *size* is necessary, not sufficient.

**Freeze record (2026-11-04).** `reports/phase2/partitions/psych101.json` — 7 families, 23 experiment
files, test-partition SHA-256 `7dc2e7798f57d3fa9ac3c73c2e334f6002c177506541617e2675bc8b0e508e4e`,
generated twice with identical output. No Phase II model has been fitted at the time of this freeze.

### Equal tuning protocol
Every model class gets the same grid size (≤ 24 configurations) and the same tune-partition
objective (mean held-out NLL on tune participants / seeds). Grids are committed before tuning.
Fits at a grid edge are reported.

## 5. Rules

1. A hypothesis, its falsifier, datasets, baselines and metrics are written down before data are touched.
2. Development and tuning use dev/tune partitions only; the test partition is read by no human or
   agent until the freeze record (`reports/phase2/freeze/<id>.json`: code commit, model config hashes,
   preregistration hash) exists.
3. One confirmatory evaluation per preregistration. Failures are recorded with equal prominence.
4. Confirmatory runs require a clean git tree; manifests must not carry `+dirty`.
5. The lane that built a model does not run its confirmatory evaluation; the critic reproduces it.
6. Every ledger row links to an artifact produced by code in this repository.
